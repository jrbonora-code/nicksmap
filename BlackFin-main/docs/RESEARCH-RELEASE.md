## Working scope

The authenticated entry point is `/research`. A single validated query supplies the property map, grid, full matching count, lender/maturity summaries and inspector. Grid sorting follows the server result order, including missing values last. The September 15 local UI pass adds cluster narrowing: a cluster click reads its member points, fits their bounds and applies their exact property IDs to that query. IDs must be unique provider identifiers, at most 500; larger clusters ask the operator to zoom or filter, without truncation. The Selected cluster chip clears the ID filter while retaining other filters, including a selected rectangle. IDs persist through saved analyses and case origins. Panning changes the view only; Search this view or a drawn rectangle changes the query. The map observes container resizing and fits initial results or changed query populations, while sorting, assumption-only changes and manual panning do not reset the view.

A point click or keyboard activation opens an anchored, scrollable preview. A grid row click or Enter expands one Community full-width detail row directly beneath the property; another click, Collapse preview or Escape closes it. Both previews show address, county, reported owner, provider and licensed units, scenario debt with its lender and reported maturity, required NOI and value already computed by the server, OZ status, source retrieval date and saved strategy-case count. Unknown values and source/address conflicts remain visible. Open full evidence selects the property and opens the existing inspector, retaining its financing form, scenario saves and strategy-case workflow. On mobile, previews are the initial detail surface; the inspector requires that explicit action (or a saved selected-scenario replay). An explicitly selected source snapshot supports historical saved views. This UI pass was released on September 15, 2026 through PR #10 as main `be917d5`; Railway deployment `05aef71b` reached SUCCESS and the anonymous checks in the handoff passed.

The initial view selects records with reported mortgage entries. Reset filters reveals the full acquired property universe. Ownership, county, lender, mortgage coverage, recorded amount, reported maturity, provider-unit range, address association, tract eligibility and rectangular bounds are available. Different mortgage predicates must match the same native entry. The lender and maturity tabs summarize all mortgage observations on the matching properties, with explicit denominators.

An independent Licenses tab retains searchable source-native records, including the unmatched subset. License search does not alter the property map. No license is represented by an invented property or county-centroid location. All 67 counties remain the intended eventual scope; the acquired baseline covers seven counties only.

## Storage, identity and access

Migration `005-research.sql` is additive and preserves migrations 001–004 and all existing workspace history. It separates stable provider identities from immutable source observations, snapshot projections, geometries, import attempts and saved analyses. A provider identity is not declared to be a verified community, parcel, building or financing facility. Native licenses, property records, mortgage entries and candidate associations remain separate observations.

Import is an explicit operator CLI action with database credentials, not an HTTP upload endpoint or an app-startup task. A transaction and advisory lock protect the import and activation. A repeated bundle creates a replay record without duplicate identities, observations or debt. A failed import rolls back and retains the previous active snapshot. A new bundle creates a new immutable snapshot. Replaying an older bundle does not silently reactivate it.

All data, tract, license, history, saved-analysis and property endpoints check the existing workspace identity server-side. They return private/no-store responses. Saved-analysis writes also require the configured origin and recompute results on the server. Source exports, bundles, browser captures, credentials and database backups are ignored and excluded from Docker build context.

The public basemap hosts are explicitly allowed in CSP; script nonce restrictions remain. The referrer policy sends only the app origin to external hosts. No property financials or credentials are sent to tile providers. Interactive street tiles follow the [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/), with visible attribution and normal browser caching, no prefetch/download, and no no-cache override. Aerial imagery uses the [USGS/USDA NAIP image service](https://imagery.nationalmap.gov/arcgis/rest/services/USGSNAIPImagery/ImageServer); acquisition dates vary and are not presented as current imagery.

## Financial contract: threshold-1

New scenarios default to the current calendar date in `America/New_York` (Eastern time, including daylight saving), independent of the browser or server timezone. The analyst can change that date; explicitly supplied and saved `asOf` dates are preserved without timezone conversion. This default-date correction does not change threshold arithmetic or the `threshold-1` model version.

Financing assumptions are visible and explicitly illustrative: scenario date, nominal annual rate, monthly amortization, term, entire-term interest-only option, DSCR after reserves, NOI debt yield, LTV and annual reserves. They are not lender quotes, approved program thresholds or owner policy. Every supported grid row runs the same model. The inspector can select another recorded entry or an explicit analyst debt target. Save view retains query, source snapshot, model version, assumptions and server-computed results; Save this scenario additionally retains the selected property/instrument and target.

- Required NOI is the greater of annual debt service × minimum after-reserve DSCR + annual reserves, and debt target × minimum NOI debt yield.
- Required collateral value is debt target ÷ maximum LTV. It is separate from the income constraint.
- Monthly end-period payment uses nominal annual rate / 12. Annual service is a 12-month run rate. The balance at term is reconstructed month by month. No floating-rate, IO-transition, fees, escrows or lender rounding convention is inferred.
- Supported principal: positive whole USD cents, at most USD 10 billion. Rate: 0–50%; term and amortization: 1–600 months; amortizing term cannot exceed amortization. Unsupported/missing inputs produce no result. Values are unrounded mathematical screen values and rounded to whole USD only for display.
- Actual NOI, actual payoff and actual funding gap remain null. Current operating performance, actual refinance gaps, per-unit debt ratios and calibrated grades are not supplied by this snapshot.

The local debt-basis-2 implementation selects a qualified instrument observed on that property alone, preferring a provider-reported first lien, then the newest recording date, then stable ID. Aggregate/multiple amounts, truncated amounts, conflicting terms, possible duplicate facilities and provider-closed entries are excluded from recorded-basis thresholds and lender totals. Missing qualification fields in older snapshots also block those calculations until an explicit reimport. A null loan type is a retained provider unknown, distinct from metadata discarded by the old parser. Missing recording dates sort after dated instruments within each lien rank. Shared instruments remain excluded from property defaults; explicit selection retains whole-instrument scope. These rules do not establish complete collateral or current obligation. Analyst targets remain explicitly labelled, including when equal to a recorded amount. See [the local debt-basis slice](DEBT-BASIS.md) for verification and release requirements.

Lender aggregates group only by county plus recorded document identifier; ambiguous identity/terms remain outside grouped totals. These are recorded-instrument observations, not a complete facility register or current lender exposure. No amount is allocated across shared collateral. Distinct recorded documents can still relate to one financing facility; instrument-group totals must not be relabeled as verified facility totals.

## Strategy cases

No authenticated production case was created during the release. See the [handoff](HANDOFF.md) for the full verification record.

A case starts from one research property record in one source snapshot and, optionally, one recorded mortgage entry observed on that record or an explicit analyst debt target. Creation copies the record, the selected entry, the property's source list, the research filters in force, the financing assumptions in force and the `threshold-1` result for the debt basis into an immutable origin (`research_strategy_cases`). An explicitly entered amount is recorded as an analyst target even when it equals the recorded amount; provenance follows how the amount was supplied. A later import never rewrites the origin. Every save appends a version (`research_strategy_case_versions`) with state, lane, content, reason, actor and time; both tables reject updates and deletes. Saves require the previously read version number and a client request ID; identical retries return the saved result, changed payloads with a reused ID are refused, and concurrent saves against the same version serialize under a row lock. Case creation and versions are audited.

The inspector only renders property evidence whose snapshot matches the active result, and the case is opened against that same snapshot, so an origin cannot be captured from evidence other than the evidence on screen.

Evidence register (model `strategy-case-2`, `lib/research/case-model.ts`): each version carries up to fifty entries, each with a stable identifier, the claims it supports or contradicts, an evidence class, source and location, effective date or period covered, obtained date, covered scope (entity, instrument or parcel), what it establishes, its limitations, reviewer and review date. Documents are not uploaded and entries are not linked to manual deal evidence. A claim asserted in any state needs a supporting entry: a deadline basis beyond the recorded maturity, a reconciled or conflicting collateral scope, permissioned current operating evidence, a verified payer relationship, identified decision authority, a recorded lender or program review, agreed fees (an executed agreement) and any billed, collected or realized amount (a documented outcome). An entry supports auditability; it does not prove the source true.

States and gates: observed lead and hypothesis carry no fee, cost, cash, capital, billed or collected amounts, no fee basis and no preferred alternative; a hypothesis needs a hypothesis, need, candidate payer type, operator role, lane, supporting and contrary evidence, the test that would reject it and a next action; a documented case additionally needs the evidenced deadline basis, collateral scope and operating evidence and a compared ordinary-refinance or no-action alternative, while fee terms may stay unknown or be recorded as none proposed; an executable proposal additionally needs the evidenced lender or program review, decision authority and payer relationship, a fee position (proposed with its amount and basis, or none proposed) and explicit cash and guarantee exposure (zero is allowed, unknown is not); agreed needs the evidenced executed agreement with an agreed fee amount or documented contingent terms; outcome recorded needs the documented outcome as evidence and no engagement, so ordinary refinancing and no action are outcomes; rejected and deferred record reasons, and deferred records reconsideration conditions. Agreed fees are recorded only from the agreed state onward and stay recorded when a case is later deferred or rejected. Progress can stop or move back at any state.

Alternatives run the existing `threshold-1` adapter against the case's fixed debt basis and are recalculated on the server; submitted results are discarded. A case without a debt basis records alternatives without assumption comparison. Proposed, agreed, billed, contingent, delivery-cost, cash, guarantee, investor-capital, collected and realized-cost amounts are separate recorded inputs in whole cents; no fee, return or probability is calculated. Annual reserves in every scenario input are parsed as exact decimal dollars through the shared scenario fields.

Screens: the property inspector lists a record's cases and opens a new one from the selected instrument or analyst target; the research Cases tab lists saved cases, shows each debt basis with its target, shared-collateral and conflicting-terms badges, and marks whether each case's property is inside the active result and whether the case came from the active snapshot; `/research/cases` lists and filters cases; `/research/cases/[id]` edits the next version beside the origin panel (including the captured filters) and version history. An empty missing-input register reads as not assessed. All routes require the workspace identity; writes require the configured origin.

Boundaries: a case is a research artifact, not a qualified deal, an available transaction, an authorization to contact anyone or a fee forecast. The QA walkthrough exercised the gates with entered statuses and synthetic evidence entries; no property has been documented from permissioned evidence. Cases are not linked to manual deals or evidence records, are not exportable and are not compared across cases. Base, adverse and improving scenario variants under one alternative are not yet modelled; the unique-kind rule means three sensitivities on one strategy currently need separate alternatives.
